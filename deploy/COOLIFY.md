# Deploying MinecraftServerTool on Coolify

This guide deploys the stack as a **Coolify Docker Compose service** that pulls
the images published by the GitHub Release workflow. Nothing is built on the
Coolify host.

The stack is three services plus the Minecraft servers it spawns:

| Service    | Image                                         | Role |
|------------|-----------------------------------------------|------|
| `mc-tool`  | `ghcr.io/dajda2371/minecraftservertool`       | Web panel + API. Talks to the Docker socket to spawn one container per Minecraft server. |
| `postgres` | `postgres:16-alpine`                          | Database. |
| `infrared` | `haveachin/infrared`                          | Minecraft reverse proxy on TCP 25565, routes by hostname (`<server>.mc.<MC_DOMAIN>`). |
| spawned    | `ghcr.io/dajda2371/mc-server-base`            | One per Minecraft server, created by `mc-tool`, joins the `mc-net` network. |

## Prerequisites

- A Coolify v4 server with the Coolify proxy (Traefik or Caddy) enabled.
- DNS:
  - panel domain, e.g. `panel.example.com` → server IP
  - wildcard `*.mc.example.com` → server IP (Minecraft hostnames)
- Firewall: TCP **25565** open to the internet (Minecraft traffic does not go
  through the HTTP proxy). Coolify already handles 80/443.
- The GHCR packages must be pullable from the host (public, or `docker login
  ghcr.io` on the host).

## Create the resource

1. Coolify → your project/environment → **New Resource** → **Docker Compose**
   (the empty / "paste your own" variant).
2. Paste the contents of `deploy/docker-compose.coolify.yml` (attached to every
   GitHub Release as well) and save.
3. **Environment Variables**:
   - `MC_DOMAIN` (required): base domain, e.g. `example.com`. New servers get
     hostnames like `survival.mc.example.com`.
   - `VERSION` (optional): release tag without the `v`, e.g. `1.4.0`. Defaults
     to `latest`. Pin it in production.
   - `SERVICE_PASSWORD_POSTGRES` is generated by Coolify. Leave it.
4. **Domain for the panel**: Coolify reads `SERVICE_FQDN_MC_TOOL_8000` from the
   compose file and generates a domain for the `mc-tool` service routed to
   container port 8000. Change it to your own domain in the service's
   *Domains* settings, e.g. `https://panel.example.com`. If the generated
   domain does not appear, add it manually there as
   `https://panel.example.com:8000`.
5. **Deploy.** First login is `admin` / `admin`; change it immediately in the
   panel.

## What the compose file does differently (and why)

Coolify rewrites compose files before deploying:

- `container_name` is replaced by `<service>-<uuid>`. The app therefore finds
  the Infrared container through compose labels (`com.docker.compose.project`
  + `com.docker.compose.service=infrared`), not by a fixed name. You can force
  a name with the `INFRARED_CONTAINER` env var if ever needed.
- Named volumes are prefixed with the resource UUID. The app discovers the real
  volume name by inspecting its own `/app/data` mount, so spawned servers mount
  the right data. Infrared's config uses its own named volume
  (`mc-infrared-config`) because Coolify does not reliably rewrite `subpath`
  mounts.
- The panel port 8000 is only `expose`d, never published. Coolify's proxy
  terminates TLS and forwards to it (WebSockets included).
- `EXTERNAL_HTTPS_PROXY=true` disables the built-in nginx + certbot HTTPS
  feature in the panel's *System* tab. It would otherwise try to bind host
  ports 80/443 that belong to Coolify's proxy.
- `FORWARDED_ALLOW_IPS=*` lets uvicorn trust `X-Forwarded-*` headers from the
  proxy.
- Only `ports: 25565:25565` on `infrared` is published; Minecraft is plain TCP.

Spawned Minecraft containers carry only `com.docker.compose.*` labels, not
Coolify's `coolify.*` labels, so **Coolify leaves them alone** when you
redeploy or restart the stack. Their data lives in the `mc-data` volume.

## Upgrading

Set `VERSION` to the new release tag and click **Redeploy**. Database schema
updates run automatically at startup. If you use `latest`, use *Pull latest
images & restart*.

## Large world uploads / downloads

The panel streams world archives with no size limit and up to 15-minute
timeouts. Traefik's default read timeout (60 s) can cut very large uploads. If
you hit that, add to the proxy's entrypoint configuration in Coolify (*Servers →
Proxy → Configuration*):

```
--entrypoints.https.transport.respondingTimeouts.readTimeout=900s
--entrypoints.http.transport.respondingTimeouts.readTimeout=900s
```

## Security notes

- `mc-tool` mounts `/var/run/docker.sock`. That is root-equivalent access to
  the host; it is required to spawn server containers, same as with the
  classic deployment.
- Change the default `admin` password right after the first login.
- Keep `VERSION` pinned; `latest` moves with every release.

## Troubleshooting

- **"no available server" on the panel domain**: Traefik has no healthy
  container to route to. Check `mc-tool`'s logs in Coolify; the usual cause is
  the database rejecting the password (see next item) so the app never starts.
- **`password authentication failed for user "mcserver"`**: the Postgres data
  volume was initialised under a different password than the one Coolify now
  injects (for example by an earlier deployment of the root compose file).
  Either delete the `mc-postgres-data` volume if the database is still empty, or
  reset the role to the current value from the host:

  ```bash
  docker exec -it postgres-<uuid> sh -c 'psql -U mcserver -d mcserver -c "ALTER ROLE mcserver WITH PASSWORD '"'"'$POSTGRES_PASSWORD'"'"';"'
  ```
- **Infrared restarts with `mkdir ./proxies: file exists`**: Infrared found a
  `proxies/` directory but no `config.yml` in its volume, which happens when it
  starts before `mc-tool` has written the config. It recovers on its next
  restart once `mc-tool` is healthy; images from v0.4.1 on no longer trigger it.

- **Panel unreachable**: check the `mc-tool` domain in Coolify points to port
  8000 and that the container is healthy (`/healthz`).
- **"Proxy: not found" in the panel**: the Infrared container could not be
  located. Confirm the `infrared` service is running in the same Coolify
  resource, or set `INFRARED_CONTAINER` to its container name.
- **Players cannot connect**: verify `*.mc.<MC_DOMAIN>` resolves to the host,
  TCP 25565 is open, and the server's hostname shows in the panel's Infrared
  routes page.
- **Server creation stalls on first use**: the `mc-server-base` image is pulled
  in the background at startup; check the `mc-tool` logs for pull errors (e.g.
  a private GHCR package).
